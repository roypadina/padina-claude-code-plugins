# Vault review

`VP="${CLAUDE_PLUGIN_ROOT}/scripts/vault.py"` — python3, stdlib only; `python3 "$VP" --help` lists every command. Not installed as a plugin → use the repo's `scripts/vault.py`. Every command takes `--vault DIR`; without it, the nearest ancestor of cwd holding `.obsidian/` or `_Vault/` is used.

## Hard rules

- Vault = argument, else cwd discovery, else ask. Never guess between two vaults.
- Judge structure from folders, file names, frontmatter and headings only (`vault.py tree`, `head -n 15`, `grep -m 1`). Never read note bodies for this; never print secrets found in notes.
- Git: `git -C V -c core.quotepath=off status --short` first (plain `git status` escapes non-ASCII names). Never `reset`, `checkout`, `clean`, `stash`, `commit` or `push`; uncommitted user changes stay exactly as they are. Moves go through `vault.py move` (git mv when tracked, plain mv otherwise, case-only renames handled).
- Never touch `.git`, `.obsidian`, `.trash`, `.st*`. Inside the vault the script writes `_Vault/`, `Index.md` and — on moves/rewrites — the notes' links and path text; outside it only via `refs rewrite --apply` on the configured consumer roots.
- Approval gate: no move, rename or `--apply` before the human approved the exact list. Present, wait, apply that list only.
- Obsidian does not notice external renames; the script fixes links, the app does not. If Obsidian is running, ask the human to close it first (never drive the GUI); if they decline, proceed — Obsidian reloads the tree, links are already fixed on disk.
- Hand edits of paths are judged by meaning, not by string: `Mac/PC`, `TCP/IP`, `I/O` can be product or concept pairs, not vault paths. Rewrite only when the text continues into a real vault sub-path or plainly names the folder. The script's `--bare` mode marks unverifiable hits `?` for exactly this reason.

## Workflow

0. **Locate + state.** `python3 "$VP" tree --vault V --depth 2`; `git -C V -c core.quotepath=off status --short | head -40` (+ `| wc -l`). Not a git repo → skip git everywhere below; `changes` diffs against `_Vault/snapshot.json` (written by `mark`).
1. **Init if unmanaged** (no `_Vault/Vault Structure.md`): `python3 "$VP" init --vault V` (writes config, Structure note, subjects, index — no review marker; `mark` comes at the end). Then fill `_Vault/Vault Structure.md` — Taxonomy rows, one Folder map line per folder (what it holds structurally, not its content), the Naming rule derived from the existing names, Writers registry (step 5); `check` counts every `(describe: …)` placeholder left — and `_Vault/vault-manager.json`: `consumers.roots` (places outside the vault that mention vault paths: Claude config and memory, skills, plugin source repos, settings files, scripts, LaunchAgents, app configs), `consumers.report_only` (never written, only listed: installed copies such as `plugins/cache` and `plugins/marketplaces`, and shared or versioned repos where a change needs a PR, e.g. `~/Code/<org>/*/`), `index.collapse` (machine-written bulk folders), `index.split_kb` (default 20), optional `consumers.needles` when the vault is referenced by another name (symlink, alias, `Obsidian <Name>/…`). Ask the human for the roots if unknown. Empty vault: ask at most three questions (what the vault is for, which life/work areas, which tools write to it) and derive the taxonomy from the answers.
2. **What changed.** `python3 "$VP" changes --vault V` — committed since the marker, uncommitted now, git renames and likely human moves collapsed to folder level (`--all` for the file pairs), folders with no tracked file; non-git: snapshot diff with removed + added pairs collapsed the same way. That list is what needs re-thinking; untouched areas are not re-evaluated unless the taxonomy itself changes. No marker → the whole vault is new.
3. **Evaluate.** Read `references/taxonomy-guide.md`. Check: one top-level axis, clean personal / technical / work (+ infra / setup / reference where the vault needs them) separation, single-note folders, typos and abbreviations, machine-owned bulk, folders with the same meaning, loose root notes, naming. For every candidate move get its cost first: `python3 "$VP" refs scan --vault V --path "Old/Path"` (outside references, in-vault links) and `python3 "$VP" refs scan --vault V --bare "Old/Path" --anywhere` (bare mentions, incl. `<vault name>/Old/Path` forms; `report_only` hits are listed separately — each one is a PR or a reinstall, so they pin the path).
4. **Propose, apply nothing.** Table: `# | Change | From → To | Notes | Outside refs | Bare | Links | Why`. Split a cheap set (typos, loose notes, single-note folders) from a structural set (top-level moves); recommend one option and say what it costs. Also list, independent of the moves: stale outside references (`[STALE]` / `[partial]` from `refs scan`), broken links, ambiguous basenames.
5. **Writers registry.** `python3 "$VP" refs scan --vault V` without `--path`: every outside file that mentions the vault is a candidate writer. Read each hit's context (`sed -n 'N,Mp'`) and fill Writer / Kind / Source / Vault paths / Access per `vault-writers`. A writer whose path comes from a config file (plugin `pluginConfigs` in settings files, an env var, a constant in a script) lists that file as a Source too. Scripts that get the vault dir as an argument hold only relative folder names and never match the scan: also grep the workspaces and script dirs that built the vault for its top-level folder names (`grep -rlF "Folder/" ~/bin <task workspace>`); once registered, `check` → `writers vs sources` keeps watching them. Write the rows now, before any move.
6. **Apply, after approval, one move at a time.**
   1. `python3 "$VP" move --vault V "Old" "New"` — fixes in-vault links, backticked/full-path/frontmatter path text (history in the Review log and collapsed mirrors are left alone), `index.collapse`/`ignore` entries, subjects; removes the folder it emptied.
   2. `python3 "$VP" refs rewrite --vault V "Old" "New"` (dry run: full `<vault>/Old` paths outside the vault) → review → `--apply`. `report_only` copies are listed, never edited: fix at the source repo, then tell the human which installed plugins need update/reinstall.
   3. `python3 "$VP" refs rewrite --vault V "Old" "New" --bare` (dry run: bare mentions in files that also mention the vault; `--anywhere` for every file under the roots). Each hit has an id and a verdict: `ok` = continues into a real sub-path, `?` = check the meaning. Decide per hit, then `--apply --only 1,4,7` (or `--only all` = every `ok` hit). Paths composed in code (`VAULT + '/X'`, f-strings, `[partial]` hits) are hand edits — open the Source from the registry.
   4. Update the registry rows and the Folder map line (backticked paths were rewritten already; prose by hand). A typo fix is a move too.
7. **Regenerate.** `python3 "$VP" index --vault V` (folders whose index would exceed `index.split_kb` get their own `_Vault/Index/<Folder>/<Sub>.md`). Set a one-line subject for every top-level and depth-2 folder: `python3 "$VP" subject set --vault V "Folder/" "…"` (folder keys end with `/`). `python3 "$VP" subject missing --vault V` → fill the notes whose auto-subject is empty (frontmatter `description`, else first body line). `python3 "$VP" check --vault V` must end with 0 folders not described and 0 writer problems. Machine-written mirrors (collapsed folders) still hold old paths until their writer regenerates them — say so in the report.
8. **Log + mark.** Add one line under `## Review log` in the Structure note (date, what changed, what was deferred and why), then `python3 "$VP" mark --vault V` — log first, so a snapshot-mode vault does not report its own log line as a change next time.
9. **Report.** Moves applied; files rewritten outside the vault (full list, hand edits marked); installed plugins to update and report-only repos that need a PR; links fixed / still broken; registry rows added; git vaults: `git -C V -c core.quotepath=off status --short | head -60`. No commit unless asked.

Partial runs are normal: "re-index" = step 7; "what changed" = step 2; "init" = step 1; "propose only" = steps 0–4.
