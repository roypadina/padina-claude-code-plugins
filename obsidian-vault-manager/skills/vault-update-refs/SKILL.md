# Update references after moves

`VP="${CLAUDE_PLUGIN_ROOT}/scripts/vault.py"`. Dry run is the default everywhere; `--apply` writes. Nothing is committed.

1. **Find the moves.** `python3 "$VP" changes --vault V` → `likely human moves` (deleted + added with the same name, collapsed to the folder move that explains them; `--all` lists the files), git renames collapsed the same way, and for non-git vaults the snapshot's removed + added pairs. Confirm the list with the human when it is not obvious; each becomes an `OLD → NEW` pair at folder level (`Projcts` → `Work/Projects`), not per file.
2. **Find what points at the old paths.** `python3 "$VP" refs scan --vault V` — `[STALE]` and `[partial]` full-path references outside the vault, broken in-vault links, ambiguous basenames. `--path "Old"` narrows to one move. `python3 "$VP" refs scan --vault V --bare "Old" "New"` lists bare mentions with a verdict per hit.
3. **Rewrite, one pair at a time.**
   1. `python3 "$VP" refs rewrite --vault V "OLD" "NEW"` → review every file and line printed → same command with `--apply`. Covers: consumer roots (literal `<parent>/<vault>/OLD` forms, including `~/` forms under HOME), in-vault path-style links, unique basename links on a note rename, backticked / full-path / frontmatter path text in notes (not the Structure note's Review log, not collapsed machine mirrors), `index.collapse` and `ignore` config entries, subject keys.
   2. `python3 "$VP" refs rewrite --vault V "OLD" "NEW" --bare` → one line per path-shaped mention (`OLD/…` or `<vault name>/OLD/…`; a bare word or a quoted label is never listed): `[id ok]` continues into a real sub-path or is exactly the folder, `[id ?]` the continuation does not exist. Read every `?` in context (`sed -n 'N,Mp' file`): product or concept pairs (`Mac/PC`, `TCP/IP`) and history ("moved here from `Old/`") stay as they are. Then `--apply --only 2,5,9` with the ids you confirmed (`--only all` = every `ok` hit, never the `?` ones). Default scope = files that also mention the vault; `--anywhere` scans every file under the roots when a script refers to the vault only by a bare path.
   3. `report_only` roots (installed plugin caches, shared repos): never edited — both full-path and bare hits there are listed under their own heading; fix the source repo (PR) and tell the human which plugins to update/reinstall.
   4. Paths composed in code (`VAULT + '/Inbox'`, f-strings, `[partial]` hits) do not match literally: open the Source from the Writers registry and fix by hand, then run the writer's own self-test if it has one.
   5. Settings files that exist in several copies (one per config dir) are all listed as roots; confirm every copy was rewritten and is still valid JSON (`python3 -c 'import json,sys; json.load(open(sys.argv[1]))' FILE`).
4. **Leftovers.** `python3 "$VP" refs scan --vault V --all | grep -A200 'in-vault links'` → fix remaining links by hand (`sed -i ''` on the exact line) or report them as pre-existing when the target never existed.
5. **Registry + map.** Update the Writers registry rows and the Folder map lines that name the moved paths (prose parts; backticks were rewritten already).
6. **Regenerate + verify.** `python3 "$VP" index --vault V`; `python3 "$VP" check --vault V` → 0 missing folders, 0 writer problems; `python3 "$VP" refs scan --vault V --path "NEW"` shows `[ok]`.
7. **Report.** Files changed outside the vault (full list; bare-mode hits applied and skipped), plugins to reinstall, links fixed / still broken, `git -C V -c core.quotepath=off status --short | head -40`. Re-test any writer whose Notes field says so.
